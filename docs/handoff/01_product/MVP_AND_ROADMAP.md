# MVP Model and Roadmap Philosophy

> **Status:** settled process, evolving scope

## There is not only one MVP

The user described a staged widening strategy:

### MVP-0 / private prototype

For the developer and close friends. Purpose:

- prove the interaction loop;
- expose obvious UX failures;
- generate ideas;
- learn what is fun before broadening scope.

### Core-mechanics MVP

The next meaningful stage should demonstrate the real pillars strongly enough to show more people:

- persistent character/world;
- deep enough fishing;
- discovery;
- economy/gear;
- world progression;
- social Telegram interaction;
- coherent player UX.

### Expanding playtest stages

Broaden the audience progressively, using actual player confusion/behavior as design input.

## MVP success criterion

A tester should not merely say “the bot works.” They should voluntarily continue interacting and ask what else exists.

Good signs:

- deliberate bait experimentation;
- theories about hidden relationships;
- chasing an escaped specimen;
- caring about personal records;
- returning when conditions change;
- exploring without being told exactly what reward exists;
- using group fishing without fear/confusion;
- understanding navigation without external instructions.

## Scope discipline

Every new system should answer one of these:

- Does it make the current loop more interesting?
- Does it prove a foundational capability needed by many future systems?
- Does playtesting demonstrate a need?

“Scalable” does not mean building generic systems in advance. It means preserving clean data/history/capability boundaries so concrete new content can be added without rewrites.

## Near-term priority after this handoff

The next iteration should prioritize **player UX and social Telegram interaction**, not more raw content. There is already enough mechanics to expose whether the interface is helping or hiding the game.
