# Player Copy Style

> **Status:** settled UX guidance

## Voice

The game can be atmospheric, curious, and occasionally strange, but ordinary UI should be concise and legible.

Avoid explaining systems like a wiki unless the player explicitly opens a detail/help view.

## Player-first rule

Every sentence should pass:

> Would this be useful/natural if the developer were not reading it?

If not, move it to logs/docs/admin tooling.

## Prefer concrete language

Bad:

> This build preserves provenance when items are removed from usable inventory.

Player version:

> Sold catches still count toward your records.

Bad:

> Group-native shared events remain a future interaction mode.

Player version:

> Everyone in this chat can cast once before the shoal moves on.

## Unknown world terms

Do not assume a new player knows “Rustwater,” “Harbor Board,” “Mara,” “Cove,” etc. Introduce nouns in context.

## Emojis

Use as visual anchors, especially for repeated concepts. Do not prefix every sentence/item just to make the message colorful.

## Mystery vs opacity

A hidden game rule can be mysterious. The **interface** should not be mysterious about what pressing a button will do.
