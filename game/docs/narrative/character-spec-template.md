# Character specification template

Use this template for recurring NPCs and other characters that need stable writing and visual identity. It is intentionally compact: record what must remain consistent, what may vary, and what is still unknown.

Do not fill every field speculatively. A blank/open section is better than invented canon.

## Character core

Describe in a few sentences:

- personality;
- motivations;
- fears / pressures;
- contradictions;
- what they know that matters;
- what they want from the player/world;
- how they may change.

### Voice

Record speech rhythm, vocabulary, humor, formality, habits, and things the character would **not** say. Include a few short sample lines only when they reveal voice rather than script a scene prematurely.

## Narrative state

Record durable state that can legitimately change dialogue or relationships, for example:

- world discoveries/events witnessed;
- quests/contracts involving the character;
- trust/reputation milestones;
- promises, conflicts or debts;
- player choices the character remembers;
- relationship/romance state where relevant.

Do not turn this into a universal dialogue-engine schema before several real characters expose common needs.

## Visual identity

### Recognition anchors

List the traits that must survive normal art variation:

- hair color/style;
- eye color;
- age/build;
- silhouette;
- palette;
- signature garment;
- iconic object/accessory;
- species-specific features where applicable.

### Clothing and palette

Describe the canonical base outfit and its material/world logic. Separate **canonical anchors** from optional outfit variants.

### Expression / pose set

List expressions or poses that are likely to recur in portraits, dialogue, scenes and promo art.

### Variants

Possible categories include weather/season gear, work clothes, travel/expedition equipment, formal/event outfits, injuries, relationship/story milestones, or region-specific gear.

## Art and image use

State where this character may appear:

- dialogue portrait;
- Rich Message screen art;
- full scene/CG;
- collectible gallery unlock;
- profile/promo artwork;
- event art;
- inline/shareable card.

Record crop/aspect requirements only when the asset pipeline actually needs them.

## Tone boundaries

Record the normal presentation range (e.g. cute, neutral, intimidating, suggestive) and any hard boundaries. For romanceable characters, keep adulthood and agency explicit; do not let fanservice replace identity.

## Canonical generation fragment

Once visual identity is stable, write one reusable paragraph that describes the character without scene-specific details. Image prompts should combine:

1. the stable Rustwater world/art block from [`../art/visual-direction.md`](../art/visual-direction.md);
2. this character's canonical fragment;
3. scene/emotion/weather/camera/output-specific instructions.

## Open questions

Keep unresolved character questions here until they become important enough to settle. When a decision becomes canon, move it into the appropriate section rather than preserving a decision history.
